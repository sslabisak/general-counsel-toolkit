# IP Ownership Checklist

The question in every financing and sale is whether the company owns what it says it owns. This checklist answers it before anyone asks. Run it when joining as counsel, then once a year and before any transaction.

## 1. Entities

- [ ] Chart of every entity, its jurisdiction, and its owners
- [ ] Which entity employs or contracts with each person who builds the product
- [ ] Which entity holds each registered right and each customer contract
- [ ] Intercompany agreement in place wherever one entity develops and another sells (license, services, and data processing)

## 2. People

For every founder, employee, contractor, advisor, and agency that has contributed to the product, brand, or content:

| Name | Role | Dates | Signed assignment to the correct entity | Present-tense assignment language | Covers work before signing | Prior employer or university claim checked | Gap and fix |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

- [ ] Founders: assignment of everything created before incorporation
- [ ] Employees: invention assignment and confidentiality agreement signed at or before start
- [ ] Contractors: written agreement with an express assignment; do not rely on "work made for hire" language alone for contractor-written software
- [ ] Contractors outside the United States: assignment valid under local law, including waiver of moral rights where permitted
- [ ] Departed contributors: confirmatory assignment obtained for any gap

## 3. Code and data

- [ ] Source code repositories owned by a company account, with access tied to company identities
- [ ] Open-source inventory: component, license, and how it is used and distributed
- [ ] No copyleft license triggered by the way the product is distributed, or a documented plan if one is
- [ ] Third-party notices shipped with distributed software
- [ ] AI-assisted code: tools used, their terms, and a human author of record for material contributions
- [ ] Rights to every dataset used to build, train, or enrich the product
- [ ] Customer contracts reviewed for any grant of ownership in deliverables or improvements

## 4. Registered rights

| Right | Owner of record | Jurisdictions | Status | Next deadline |
|---|---|---|---|---|
| Trademarks | | | | |
| Patents and applications | | | | |
| Copyright registrations | | | | |
| Domains | | | | |
| Social handles and app store accounts | | | | |

- [ ] Every registration is held by the company and not by an individual
- [ ] Domains and accounts are registered to a company email and a shared credential vault
- [ ] Clearance search done for each mark in use but not filed

## 5. Trade secrets

- [ ] Written list of what the company treats as a trade secret, described specifically
- [ ] Access limited to people who need it, with access logs kept
- [ ] Confidentiality agreements with everyone who has access
- [ ] Offboarding: access removed and return of materials confirmed in writing on the last day
- [ ] Development history kept (commits, design documents, dated notes) to prove independent creation

## 6. Inbound rights

- [ ] Licenses for every third-party component, font, image, and dataset in the product
- [ ] Any exclusivity, field restriction, or change-of-control clause in an inbound license
- [ ] API and platform terms for each dependency (see the platform dependency register)

## 7. Output

A one-page table: confirmed, fixed, and open. For each open item, the fix, the owner, and the date.
